# PillStack — 서로 챙기는 영양제 리마인더

> v2 컨셉 기획서 · 작성 2026-09-01 · 상태: 컨셉 확정, 상세 설계 착수 전
> 한 줄 정의: **내가 영양제를 먹으면 그 사실이 곧 상대의 리마인더가 되는, 둘 이상을 위한 영양제 앱**
> 스토어 부제: **서로 챙기는 영양제 리마인더**
> 비주얼 톤: v1 리디자인('야간 조제실' — 잉크 블랙 + 캡슐 민트 + 시간대 슬롯 컬러) **그대로 유지**

---

## 1. 왜 방향을 바꾸나

v1(성분 분석 앱)은 출시 후 "한 번 쓰고 삭제" 패턴이 확인됐다. 원인은 UX가 아니라 구조였다.

- 분석은 1회성 가치다 (영양제는 30~90일 주기로만 바뀜)
- 매일 열 이유(체크·리마인더)가 분석에 종속돼 있었고, 영양제를 바꾸면 스스로 파괴됐다
- 근본적으로 **"본인 영양제"는 관여도가 낮아** 어떤 리마인더도 오래 못 간다

v2는 이 전제를 뒤집는다. **리마인더의 발신자를 시스템에서 사람으로 바꾼다.**
상대가 먹었다는 알림이 나의 리마인더가 되고, 내가 먹었다는 버튼 한 번이 상대의 리마인더가 된다. 동기는 건강이 아니라 관계다.

---

## 2. 타겟 — 그리고 과감히 버리는 것

**타겟**: 영양제를 함께 챙길 사람이 있는 사용자
- 커플 (가장 강한 코어 — 매일 연락하는 관계, 서로 챙기는 게 자연스러움)
- 친구 (운동·다이어트 메이트)
- 가족 (부모님·형제) — 부모님 케이스는 "감시"가 아니라 "안부"의 톤

**버리는 것**: 혼자 쓰는 사용자. 솔로 유저에게 이 앱은 의도적으로 비어 있다.
혼자인 홈 화면은 "함께할 사람 초대하기"가 전부다. 리마인더는 동작하지만, 이 앱의 재미는 초대해야 열린다는 걸 숨기지 않는다.
→ 부작용으로 **모든 사용자가 최소 1명을 초대하는 구조**가 되며, 이것이 곧 성장 루프다.

---

## 3. 핵심 가치와 차별점

| | 기존 복약/영양제 앱 | PillStack v2 |
|---|---|---|
| 리마인더 발신자 | 시스템 | **사람** (닉네임이 박힌 알림) |
| 가족 연결 | 부가 기능, 상대도 가입·설정 필요 | **제품 그 자체**, 상대는 링크 탭 + 닉네임 입력이 전부 |
| 동기 | 본인 건강 | **관계·연속 기록** (나 때문에 끊기면 안 됨) |
| 메인 화면 | 탭 5개, 기능 나열 | **화면 1개**: 지금 먹을 것 + 상대 현황 + 챙기기 |
| 성분 분석·DB | 전면 | **뒤로** — 신뢰 요소로만 조용히 |

## 4. 개념 모델

```
사용자(User)
 └─ 그룹(Group) N개에 속함           ← 다중 그룹 (커플 그룹 + 가족 그룹 동시 가능)
     └─ 구성원(Membership)
          - 그룹별 닉네임 (같은 사람이 A그룹에선 "자기", B그룹에선 "아들")
          - 이모지 아바타
 └─ 내 영양제(Stack) — 사용자 소유, 그룹과 무관
     └─ 슬롯(Slot): 아침 / 저녁 / 취침 전  + 알림 시각
 └─ 복용 이벤트(Intake): 날짜 × 슬롯 × 사용자 → "먹었어요" 1건
 └─ 챙김(Nudge): 보낸 사람 → 받은 사람, 그룹, 슬롯, 날짜
```

원칙:
- **영양제는 내 것, 알림은 그룹 것.** 무엇을 먹는지는 개인 설정이고, 먹었다는 사실만 그룹에 공유된다.
- **"먹었어요"는 한 번만 누른다.** 그 한 번이 내가 속한 모든 그룹에 각 그룹의 규칙과 닉네임으로 퍼진다.
- 슬롯 완료 기준: 그 슬롯에 영양제가 등록된 구성원 전원이 먹음. (그 슬롯에 등록이 없는 구성원은 계산에서 제외)

## 5. 코어 루프

```
        ┌──────────────────────────────────────────────┐
        │  ① 슬롯 시각 → 내 폰에 알림 (큰 글씨 팝업)      │
        │       └ 상대가 이미 먹었으면 그 사실을 실어서   │
        ▼                                              │
  ② [먹었어요] 탭 → 팝업 닫힘                          │
        │                                              │
        ▼                                              │
  ③ 아직 안 먹은 구성원에게 알림                        │
     "자기가 아침 영양제 먹었어요. 아직 안 먹었죠?"      │
        │                                              │
        ▼                                              │
  ④ 메인 화면 = 구성원 현황  → [챙기기] 로 직접 콕 ─────┘
        │
        ▼
  ⑤ 슬롯 전원 완료 → "오늘 아침, 다 챙겨 먹었어요 🔥 12일째"
```

②에서 ③이 자동으로 일어나는 것이 이 제품의 전부다. 사용자는 자기 것만 챙겼는데 상대를 챙긴 셈이 된다.

## 6. 화면 구조 (IA)

탭바 없음. 메인 1화면 + 진입 가능한 서브 화면.

```
[메인] 오늘
  ├─ 지금 슬롯 카드 (내 영양제 + 먹었어요)
  ├─ 그룹 섹션 × N (구성원 현황 + 챙기기)
  └─ 그룹별 연속 기록

[서브]
  ├─ 온보딩 (첫 실행 3장 → 닉네임 → 분기)
  ├─ 초대하기 / 초대 참여
  ├─ 그룹 관리 (이름·이모지·나가기·구성원 보기)
  ├─ 내 영양제  ← v1의 검색·OCR·상세·궁합이 전부 여기로 흡수
  │    ├─ 추가 (검색 / 라벨 촬영)
  │    ├─ 슬롯 배치 + 알림 시각 (v1 타이밍 추천을 기본값으로 제안)
  │    └─ 궁합 상태 (v1 분석 — 카드 1장으로 축약, 경고 있을 때만 두드러짐)
  ├─ 기록 (v1 캘린더 — 개인 + 그룹 연속 기록)
  └─ 설정 (프로필 이모지·알림·계정)

[오버레이]
  └─ 복용 팝업 (알림 탭 시 / 슬롯 시각에 앱 열려 있을 때)
```

규칙:

- 그룹은 섹션으로 위아래 나열 (스위처 없음). 그룹이 3개 이상이면 접기 가능.
- 구성원 행: 그룹 내 닉네임 · 상태(먹음 시각 / 아직 / 오늘 없음) · 아직이면 [챙기기].
- 내 행은 항상 포함 (내 상태도 이 그룹 안에서 보이는 그대로).
- 혼자인 그룹 없음 상태: 슬롯 카드 아래가 통째로 "함께할 사람 초대하기" 카드.

## 8. 복용 팝업 (알림 → 먹었어요)

기존 알림 탭 UI를 대체한다.

**트리거**
- 슬롯 알림 탭 → 앱 열리며 팝업
- 슬롯 시각에 앱이 이미 열려 있으면 팝업 즉시
- 알림 자체에도 **[먹었어요] 액션 버튼** 제공 → 앱을 열지 않고도 완료 (Capacitor LocalNotifications action type). 이 경우 팝업 없이 브로드캐스트만.

**팝업 스펙**
```
┌────────────────────────────────┐
│                                │
│         ☀ 아침 영양제           │
│                                │
│          오메가3                │  ← 큰 글씨 (24px+), 고대비
│          비타민D                │
│          유산균                 │
│                                │
│   자기는 08:12에 먹었어요 ✓     │  ← 상대가 먼저 먹었으면 표시 (동기 부여)
│                                │
│   ┌──────────────────────────┐ │
│   │        먹었어요           │ │  ← 전체 폭, 높이 큰 버튼
│   └──────────────────────────┘ │
│           10분 뒤에             │  ← 작은 텍스트 버튼 (스누즈)
└────────────────────────────────┘
```

- [먹었어요] → 복용 이벤트 기록 → 팝업 닫힘 → **메인 화면** (기본 화면이므로 별도 이동 없음) → 구성원 현황에서 챙기기 가능
- [10분 뒤에] → 스누즈 1회, 두 번째부터는 "다음 슬롯에서 다시" (무한 스누즈 방지)
- 팝업은 그 슬롯 하루 1회. 이미 먹은 슬롯은 알림 자체를 안 보냄.

**잠금화면 제약 (기술 메모)**: 잠금화면 위 전체화면 팝업(full-screen intent)은 Android 14+에서 알람·통화 앱에 제한적으로 허용된다. 스토어 검수 리스크가 있어 MVP는 **알림 액션 버튼 + 탭 시 팝업**으로 가고, 전체화면 인텐트는 검수 통과 여부를 보고 추가한다.

## 9. 알림 규칙 — 피로 방지가 제품의 생명

### 대원칙 두 가지

**① 자동 브로드캐스트는 보내지 않는다.**
"누가 먹었다"를 자동으로 전파하면 알림이 사람 수만큼 곱해지고, **그룹이 클수록 시끄러워져 오히려 지우게 되는** 역설이 생긴다.
남에게 가는 알림은 **사람이 [챙기기]를 눌렀을 때만** 발생한다. 아무도 안 누르면 알림도 0이다.
대신 "상대가 먹었다"는 사실은 (a) 내 리마인더 문구에 얹어서, (b) 앱 화면 현황으로 전달한다.

**② 모든 알림은 "받는 사람의 시간"을 기준으로 판단한다.**
구성원마다 슬롯 시각이 다르다(내 아침 07:00, 동생 아침 11:00). 보내는 사람 기준으로 판단하면
아직 먹을 시간도 안 된 사람을 재촉하게 된다. 챙김 가능 시점·야간 보류 모두 **받는 사람 기준**이다.

### 규칙표

| 이벤트 | 수신자 | 문구 예시 | 제한 |
|---|---|---|---|
| 내 슬롯 시각 | 본인 | "☀ 아침 복용 시간 — 오메가3, 비타민D"<br>(로컬 알림이라 문구 고정. "누가 먹었는지"는 탭 후 팝업에서) | 슬롯당 1회. **시각과 무관하게 항상 발송**(본인이 정한 알림이므로 야간 제한 없음) |
| [먹었어요] | – | **알림 없음** | 현황만 갱신 |
| [챙기기] | 그 사람 1명 | "동생, 엄마가 챙겨줬어요 💊" | **받는 사람 기준 슬롯당 1건**(그룹 무관·선착순)<br>· **받는 사람의** 슬롯 시각 +30분 이후에만 가능<br>· 받는 사람 야간이면 보류 |
| 슬롯 전원 완료 | **푸시 없음** | – | **인앱 축하 연출로만** 표현 |
| 초대 참여 | 그룹 기존 구성원 | "민수가 우리집에 들어왔어요" | – |

**푸시를 보내는 것은 리마인더와 챙김, 단 두 가지뿐이다.**

### 세부 규칙

**"먹은 사람"을 어디서 보여줄 것인가 — 구현 제약과 결론**

원래 의도는 리마인더 **알림 문구**에 "엄마·아빠는 드셨어요"를 얹는 것이었으나, 실제로는 불가능하다.

- 리마인더는 기기에 **매일 반복으로 예약해 두는 로컬 알림**이다. 예약 시점에 텍스트가 고정되므로
  그날 누가 먹었는지를 담을 수 없다.
- 서버에서 슬롯 시각마다 푸시를 쏘면 가능하지만, **Vercel Hobby 요금제의 cron 최소 주기는 하루 1회**라
  분 단위 스케줄링을 할 수 없다. (별도 스케줄러 도입은 v2 범위 밖)

**결론: 알림 문구는 고정하고, 사회적 신호는 알림을 탭한 뒤 열리는 복용 팝업이 전달한다.**

- 알림: `☀ 아침 복용 시간 — 오메가3, 비타민D` (고정)
- 팝업: 큰 글씨 목록 아래 **"자기는 08:12에 먹었어요 ✓"** (8장 설계 그대로)

사용자가 실제로 행동하는 지점이 팝업이므로 전달력은 크게 떨어지지 않는다.
다만 **알림만 보고 앱을 열지 않는 사용자**에게는 이 신호가 닿지 않는다는 한계는 남는다.
유료 요금제 전환이나 별도 스케줄러 도입 시 알림 문구에 얹는 방식으로 개선한다.

표기 원칙(어디에 표시하든 동일): **먹은 사람만 언급**하고, 안 먹은 사람은 아예 말하지 않는다.
시각이 달라 아직 먹을 때가 안 됐을 뿐인데 "아직이에요"라고 하면 없는 게으름을 만든다.

**[챙기기] — 선착순 1건**
- 제약은 `UNIQUE (to_user, date, slot)` — **받는 사람 기준**. `group_id`를 키에서 뺀 이유는
  다중 그룹에서 곱해지는 것을 막기 위함이다(커플 그룹·가족 그룹에서 각각 챙기면 2건이 된다).
- 이 제약이 곧 **선착순 잠금**이다. 먼저 누른 사람이 "챙긴 사람"이 되고,
  다른 구성원 화면에서는 버튼이 사라지고 **"엄마가 챙겨줬어요"** 표기로 바뀐다.
- 이미 챙김을 받은 사람에게 **버튼을 다시 노출하지 않는다** — 두 번 찌르는 것은 관계 앱에서 공격적으로 읽힌다.
- +30분 지연은 클라이언트 UI만으로는 부족하다(시간 조작 가능). **서버에서도 검증**한다.

**"전원 완료" — 푸시 없이 인앱으로만**
- 완료는 정보가 아니라 **보상**이다. 굳이 밀어낼(push) 이유가 없고, 알림 종류를 하나 줄이는 편이 낫다.
- 대상은 **그 슬롯에 영양제를 등록한 구성원만**이다. 아침에 아무것도 안 먹는 사람은 계산에서 제외한다
  (제외하지 않으면 완료가 영원히 성립하지 않는다).
- 성립 시점은 **마지막 사람이 [먹었어요]를 누른 시점**이다.
- 표현 방식:
  - 마지막에 누른 사람 → 그 자리에서 **축하 연출**(팝업이 닫히며 연속 일수 강조)
  - 나머지 구성원 → 다음에 앱을 열었을 때 **현황·연속 기록에 반영**된 상태로 확인
- 연속 일수를 강조하되 마일스톤(7·30·100일)은 연출을 다르게 한다.
- 야간 처리 고민이 원천적으로 사라진다(푸시가 없으므로).

**야간 제한**
- 고정 시간대(기본 22:00~07:00, 받는 사람 기준)로 판단한다. 슬롯 시각 기준으로 하면 사람마다 달라 예측이 어렵다.
- **본인 리마인더는 제한하지 않는다.** 취침 전 슬롯을 00:30으로 정한 사람이 자기 알림을 못 받으면 안 된다.
- 따라서 야간 제한이 실제로 적용되는 대상은 **챙김 하나뿐**이며, 보류했다가 다음 발송 가능 시점에 전달한다.

**다중 그룹**
- [먹었어요] 1회 → 소속 그룹 각각의 현황이 갱신된다.
- 알림 문구의 이름은 **그 그룹에서의 닉네임**을 쓴다 (A그룹 "자기", B그룹 "아들").
- 챙김은 위 제약대로 그룹과 무관하게 받는 사람 기준 1건이다.
- 연속 기록은 그룹별로 따로 센다.

### 결과: 한 사람이 하루에 받는 알림

푸시는 **리마인더와 챙김뿐**이다. 슬롯 3개 기준 **최대 6건**(리마인더 3 + 챙김 3), **실제로는 3~4건**.
챙김은 조건부(누가 눌러야 발생)이고, 자동 브로드캐스트가 없으므로 **그룹 크기가 커져도 알림량은 늘지 않는다.**

| 설계안 | 4인 그룹 · 아침 슬롯 알림 수 |
|---|---|
| 무규칙 브로드캐스트 | 12건+ |
| 자동 브로드캐스트 + 챙김 + 완료푸시 | 약 3건 |
| **최종안**(리마인더 + 챙김만) | **1~2건** |

## 10. 온보딩 — 3장 + 닉네임 + 분기

첫 실행(최초 로그인) 직후. 각 장은 버튼 하나를 설명한다.

| 장 | 카피 | 화면 |
|---|---|---|
| 1 | **먹으면, 알려져요** | [먹었어요] 누르는 손 → 상대 폰에 알림 뜨는 모션 |
| 2 | **깜빡한 사람, 콕 찔러요** | [챙기기] → "자기야 영양제 💊" 알림 |
| 3 | **같이 이어가요** | 두 사람 현황 + 🔥 12일째 |

→ **닉네임**: 그룹 참여 시점마다 묻는다 — *"나는 이 그룹에서 [ 자기 ]로 불려요"* + 이모지 선택. 초대로 들어온 경우 그룹 이름을 보여주며 묻고, 새로 만드는 경우 그룹 이름을 먼저 정한 뒤 묻는다.
→ **분기**: [초대받았어요] / [내가 시작할래요]
- 초대받았어요 → 링크로 들어왔으면 이 단계는 자동 스킵, 아니면 6자리 코드 입력
- 내가 시작할래요 → 그룹 만들기(이름·이모지) → 닉네임 → 초대 화면

로그인(Google/Kakao)은 이 흐름 **뒤**에 둔다. 온보딩·닉네임·초대까지 게스트로 진행하고, 동기화가 필요해지는 시점(그룹 생성/참여 직전)에 최소 마찰로 요청한다.

## 11. 초대 — 링크가 주인공, 코드는 보험

초대 1개 = 링크 + 6자리 코드 + QR (같은 초대의 세 얼굴). 승인 없음: 링크를 가진 사람은 그냥 들어온다.

```
[초대하기]
 ├─ 카카오톡으로 보내기    ← 기본 (OS share sheet, 카톡 우선 노출)
 ├─ 코드: 4 8 2 9 1 7       ← 옆에 있을 때, 부모님
 └─ QR
```

| 받는 사람 상황 | 흐름 |
|---|---|
| 앱 있음 | 링크 탭 → 앱 열림 → "민수님의 '우리집'에 함께할까요?" → 닉네임 → 완료 |
| 앱 없음 | 링크 → Play 스토어 → 설치 → 첫 실행 시 초대 **자동 인식** → 위와 동일 |
| 링크 없음 | 앱 → [초대받았어요] → 코드 입력 |

기술: 링크는 `pillstack.kr/i/{code}` (Android App Links, 기존 OAuth 딥링크 인프라 재활용). 설치 후 자동 인식은 **Play Install Referrer API** — 무료, 안드로이드 전용(우리 앱은 안드로이드). Firebase Dynamic Links는 종료됐으므로 사용 불가.
보안: 코드 7일 만료, 초대자에게 참여 알림, 그룹장은 구성원 내보내기 가능. 링크 유출 시 새 초대 발급으로 기존 코드 무효화.

## 13. 데이터 모델 초안 (Supabase)

```sql
groups            (id, name, emoji, owner_id, created_at)
group_members     (group_id, user_id, nickname, avatar_emoji, joined_at)   -- PK (group_id, user_id)
invites           (code, group_id, inviter_id, expires_at, used_count)
user_supplements  (기존) + slot 컬럼 (morning/evening/bedtime)
reminder_times    (user_id, slot, time)                                    -- 기존 localStorage → 서버로
intake_events     (id, user_id, date, slot, taken_at)                      -- UNIQUE (user_id, date, slot)
nudges            (id, group_id, from_user, to_user, date, slot, sent_at)  -- UNIQUE (from_user, to_user, date, slot)
device_tokens     (user_id, fcm_token, platform, updated_at)
```

브로드캐스트는 서버 함수 1개로 처리: `POST /api/intake` → 이벤트 기록 → 소속 그룹 조회 → 그룹별 미복용자 산출 → 규칙(그룹당 1회·중복 제거·야간 제한) 적용 → FCM 발송 → 전원 완료 시 완료 알림. 클라이언트는 이 규칙을 몰라도 된다.

## 14. 수익화 — 지금은 넣지 않는다

커플·친구 사이 화면에 배너 광고는 관계 앱의 톤을 깬다. v1 광고 게이트는 제거한다.

## 15. 지표

v1의 실패는 측정조차 못 한 것이었다 (Analytics shim 버그). v2는 출시 전에 계측을 먼저 고친다.

| 단계 | 지표 | 의미 |
|---|---|---|
| 온보딩 | 온보딩 완료율, 닉네임 설정률 | 첫 30초 이탈 |
| 성장 | **초대 발송률, 초대 → 참여 전환율, 인당 초대 수(k)** | 이 제품의 생존 지표 |
| 코어 | 슬롯 알림 → 먹었어요 응답률, 브로드캐스트 → 상대 응답률 | 루프가 도는가 |
| 관계 | 챙기기 발송/수신 후 응답률 | 사람 알림이 시스템 알림보다 효과적인가 (가설 검증) |
| 유지 | 설치 유지율, D7/D30, 그룹 연속 기록 중앙값, 알림 끔 비율 | 지우지 않는가 |

DAU는 보조 지표다. 앱을 안 열어도(알림 액션 버튼으로 완료) 루프가 돌면 성공이다.

## 16. 범위와 순서

**v2.0 포함**: 온보딩·닉네임·다중 그룹·초대(링크/코드/QR/설치 후 인식)·복용 팝업·알림 액션·브로드캐스트 규칙·챙기기·그룹 연속 기록·메인 1화면·내 영양제(기존 흡수)·기록·계측 수리
**v2.0 제외**: 잠금화면 전체화면 팝업, 알림톡/전화 폴백(폰 못 쓰는 부모님 세그먼트), 룰 엔진 전환, 수익화, 위젯

**순서** (각 단계는 이전 단계 없이 검증 불가한 순)
1. 계측 수리 + 데이터 모델·서버 함수 (그룹/초대/복용/브로드캐스트)
2. 초대 파이프라인 (App Links + Install Referrer) — 가장 불확실, 먼저 검증
3. 알림 파이프라인 (액션 버튼 + FCM 브로드캐스트 + 규칙)
4. 메인 화면 + 복용 팝업
5. 온보딩 + 닉네임 + 그룹 관리
6. 내 영양제(v1 흡수) + 기록
7. 스토어 등록정보 갱신(부제·설명·스크린샷) → QA → 출시
   - 비주얼 톤은 v1 리디자인 유지. 신규 화면(메인·팝업·온보딩·초대)만 기존 토큰 체계로 확장한다.

## 17. 확정 / 열린 결정

**확정**
- 스토어 부제: **서로 챙기는 영양제 리마인더** (스토어 제목·설명·온보딩 카피에 일관 적용)
- 비주얼 톤: v1 '야간 조제실' 유지 — 신규 화면도 기존 토큰(민트 브랜드, 시맨틱 3색, 시간대 슬롯 컬러)으로 확장

**열린 결정**
1. 그룹 인원 상한 (제안: 8명)
2. 그룹장 권한 범위 — 내보내기만? 초대 발급을 전원 허용?
3. 상대에게 내 영양제 목록이 보이는가 — 제안: **안 보임**(프라이버시), "먹었다"만 공유. 단 가족 그룹에서 부모님 영양제를 자녀가 대신 설정해주는 케이스는 별도 "대신 관리" 권한으로 추후
4. 스토어 정책: 알림 액션 버튼·Install Referrer 사용에 따른 데이터 보안 양식 갱신
